# 실제 Neon 연결 검증

2026-09-11 사용자가 ERP 전용 프로젝트 생성을 승인했다. `assembly-erp` 프로젝트의 `main` 브랜치, `erp_demo` DB에서 검증한다. 기존 `ji` 프로젝트는 변경하지 않는다. 공개 배포는 하지 않는다.
로컬 PostgreSQL 통합 테스트 통과나 TLS 설정 단위 테스트를 실제 Neon 검증으로 대신하지 않는다. 아래 체크는 실제 실행 결과만 반영한다.

## 연결 전에 확인할 사항

로컬 테스트 DB는 PostgreSQL 17.10이고 신규 Neon 프로젝트도 실제 서버 조회에서 메이저 17을 확인했다.
데모용 접속 URL과 마이그레이션용 URL은 **직접 연결**로 준비하고 `sslmode=verify-full`을 사용한다.
Neon 값은 추적 제외된 `.env.neon`으로만 전달한다. 기존 로컬 `.env`는 보존한다. 화면 환경 변수, 문서, 커밋, 스크린샷에 복사하지 않는다.
로컬 전용 `setup:local`은 기존 `.env`를 덮어쓰지 않는다.

## 실제 검증 체크리스트

- [x] 실제 프로젝트/메이저 버전 확인, 테스트 DB 메이저 버전 일치
- [x] 직접 연결 및 서버 인증서 검증 TLS 연결 성공: Go 클라이언트 TLS 1.3, 검증된 인증서 체인 확인
- [x] Goose 마이그레이션 적용 및 적용 이력 조회 성공: 버전 1
- [x] 품목·입고·BOM·생산 지시·부분 실적·불량 흐름과 이력 대조 성공: 실제 Neon Chromium 5개 통과, 집계 불일치 0
- [x] 유휴 컴퓨트 중단 이후 첫 요청의 재연결과 응답 확인: 실제 idle/suspend 관측, API 재시작 없이 첫 GET 200/1,617ms, 전후 재고 동일
- [x] 실제 잘못된 인증서 호스트 이름/비밀번호 연결 거절, 올바른 설정 복원 후 재연결 확인
- [x] 소스·브라우저 번들·검증 보고서의 실제 접속 문자열/비밀번호 일치 검사 통과, 애플리케이션 오류는 비밀값 없이 출력

각 항목을 실행한 날짜와 결과만 [PROGRESS](PROGRESS.md)에 기록한다. 접속 문자열은 기록하지 않는다.
의도적으로 유휴 복귀를 확인할 때 주기적 ping으로 DB를 깨우지 않는다.
계정에서 제공되는 리전 목록을 확인하고 싱가포르(`aws-ap-southeast-1`)를 선택했다. 현재 Free 조직에 0.25 CU 고정 크기로 생성했으며 플랜 변경은 하지 않았다. 무료 한도와 향후 청구 비용을 보장하지 않는다. 유휴 시간 설정 변경은 계정 정책으로 거절되어 기본값을 그대로 사용한다.

## 실행 및 검증 방법

`pnpm dev:neon`은 같은 로컬 화면/API를 Neon DB에 연결한다. `pnpm neon:migrate`와 `pnpm neon:status`는 명시적 마이그레이션/상태 조회이고, 서버 시작 시 자동 실행하지 않는다. `pnpm neon:probe`는 읽기 전용으로 실제 TLS·서버 메이저·마이그레이션 버전·집계를 확인한다.

`pnpm neon:verify`는 실제 클라우드 DB에 고유 이름의 데모 데이터를 추가하는 운영자용 검증이다. 원격 초기화·TRUNCATE·삭제는 하지 않는다. TLS와 잘못된 접속 거절 확인 뒤 별도 포트(API 18081/화면 5175)에서 Chromium 시나리오를 실행한다. 로컬 `test:integration`, `test:e2e`, `demo:reset`의 대상 제한은 바꾸지 않는다.

브라우저 단계와 같은 작업 디렉터리의 `svelte-kit sync`·타입 검사·빌드·프론트엔드 파일 변경을 동시에 실행하지 않는다. 개발 서버의 재로드가 진행 중인 저장 응답을 끊어 검증을 방해할 수 있다. 검사/빌드는 브라우저 서버가 종료된 뒤 실행한다.

유휴 단계에서는 API 프로세스를 유지한 채 쿼리를 중단한다. 제어 API의 endpoint 상태가 `idle`인 것을 실제 확인한 후 `endpoint_id`, `current_state: "idle"`, `observed_at`을 담은 JSON을 `.local/neon-idle-observation.json`에 저장하거나 표준 입력으로 보내야 재개한다. 비대화형 터미널의 stdin이 닫혀도 파일 방식으로 진행할 수 있다. 파일 확인은 로컬 파일만 읽으며 DB를 깨우지 않는다. 이전 실행의 오래된 관측이나 단순 시간 경과를 유휴 성공으로 간주하지 않는다. 첫 재개 요청의 HTTP 상태·소요 시간·재고 해시 일치와 같은 API 프로세스 유지 여부를 기록한다.

결과는 `.local/neon-verification.json`, 브라우저 상세 결과는 `.local/neon-browser-results.json`에 남는다. 이 파일들과 소스·번들의 실제 비밀값 일치 검사를 수행한다.

2026-09-11 실행은 비대화형 세션의 stdin이 닫혀 있어 유휴 단계에서 별도 제어 명령으로 인계했다. 같은 API 프로세스에 대한 첫 요청·TLS·재고 대조는 실제 통과했고 원래 제어 세션은 증거 보존 후 종료했다. 원래 명령의 exit 1을 자동 실행 성공으로 집계하지 않는다. 파일 입력 지원은 이후 추가한 테스트로 검증했으며, 수정 후 전체 Neon 명령을 다시 실행한 결과는 아니다. 정확한 실행 범위와 증거는 PROGRESS를 따른다.

TLS 판정은 Go 클라이언트의 실제 핸드셰이크와 인증서 체인을 기준으로 한다. `pg_stat_ssl`은 PostgreSQL 백엔드 연결 구간의 통계라서 프록시 앞쪽의 클라이언트 TLS 판정으로 대체하지 않는다. 이 환경에서는 클라이언트 TLS 1.3/인증서 검증 성공과 백엔드 `ssl=false`가 함께 관측되었다.
