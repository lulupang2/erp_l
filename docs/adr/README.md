# ADR — 기술 결정 기록

작성일: 2026-09-11

[PRD](../PRD.md)는 제품 요구사항, [SSOT](../SSOT.md)는 현재 상세 설계의 기준이다.
ADR은 해당 설계를 선택한 배경, 대안, 감수하는 단점과 재검토 조건을 기록한다.
아래 문서는 기존 합의와 설계에 대한 기록이며 구현·성능 검증이 완료되었다는 의미는 아니다.

## 기록 원칙

- 사용자 지정은 지정 사실을 기록한다. 수행하지 않은 벤치마크나 대안 검증을 선택 근거로 만들지 않는다.
- ‘채택’은 현재 설계에 적용한다는 뜻이다. 개별 설계 기본값을 사용자가 각각 직접 선택했다는 뜻은 아니다.
- 신규 결정은 다음 번호로 추가한다. 기존 결정을 대체할 때 새 ADR에서 이전 ADR을 참조하고 이전 상태를 ‘대체됨’으로 변경한다.
- 오탈자·링크는 기존 문서에서 고친다. 결정이 바뀌면 과거 선택 이유를 지우지 않고 대체 기록을 남긴다.
- 구체적인 수치·API 형식·업무 정책은 기준 문서를 참조해 중복 정의를 줄인다.
- 변경 시 PRD의 범위, SSOT의 현재 설계, ADR 상태가 일치하는지 확인한다.

## 공통 형식

각 ADR은 상태·출처·관련 요구사항, 배경, 결정, 대안, 결과와 단점, 검증 및 재검토 조건을 포함한다.
최초 결정 작성 시점에는 라이브러리 버전, 클라우드 요금, 성능 수치를 고정하거나 측정하지 않았다. 이후 실제 고정 버전과 검증 결과는 루트 README와 PROGRESS에서 관리하며, ADR의 선택 배경을 사후 측정 결과로 바꾸지 않는다.
