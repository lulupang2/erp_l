# ADR-0002: Go Fiber 채택과 HTTP 계층 분리

- 상태: v1 채택·구현 / v2에서도 유지; 버전별 검증은 [PROGRESS](../PROGRESS.md) 참조
- 기록일: 2026-09-11
- 출처: Go와 Fiber는 사용자 지정, 계층 분리는 기존 설계 기본값
- 관련 요구사항: [PRD-V1](../PRD-V1.md) 9절, NFR-02, NFR-05; v2 기술 스택 유지

## 배경

사용자가 백엔드 언어로 Go, 웹 프레임워크로 Fiber를 지정했다.
본 결정은 프레임워크 성능 비교나 벤치마크의 결과가 아니다.
HTTP 요청 수명과 제조 업무의 트랜잭션 책임을 분리할 필요가 있다.

## 결정

Fiber로 REST API를 제공한다. 핸들러는 요청 검증·서비스 호출·응답 변환을 담당한다.
업무 규칙과 트랜잭션은 서비스 계층, SQL 호출은 DB 접근 계층에 둔다.
서비스는 Fiber 타입 대신 표준 context.Context와 업무 입력을 받는다.
Fiber 컨텍스트를 핸들러 종료 이후 보관하지 않고 DB 호출에 명시적인 제한 시간을 적용한다.
클라이언트 연결 종료만으로 DB 작업이 자동 취소된다고 가정하지 않는다.

## 대안

표준 net/http 또는 다른 Go 라우터도 후보가 될 수 있으나 사용자 지정에 따라 채택하지 않았다.
다른 프레임워크보다 빠르거나 우수하다는 주장은 하지 않는다.
Fiber 컨텍스트를 서비스 전체에 전달하는 방식은 HTTP 수명과 업무 로직의 결합을 높여 사용하지 않는다.

## 결과와 단점

사용자가 선택한 기술로 구현하면서 업무 로직을 HTTP 없이 테스트할 수 있게 한다.
대신 입력·응답 변환 코드가 필요하고, Fiber의 컨텍스트 수명과 취소 동작을 이해해야 한다.
구현 시 선택한 Fiber 버전에 맞는 API를 확인하고 버전을 고정한다.
컨텍스트 수명과 취소 주의사항은 [Fiber 공식 문서](https://docs.gofiber.io/guide/go-context/)를 참고한다.

## 검증과 재검토 조건

핸들러 입력 오류, 서비스 오류의 HTTP 변환, DB 타임아웃을 검증한다.
필수 미들웨어나 연동이 선택 버전과 호환되지 않으면 어댑터 비용을 평가하고 필요할 때 새 ADR로 변경한다.
