# ADR-0006: 트랜잭션·행 잠금과 요청 식별자로 수량 정합성 보장

- 상태: 채택 / 구현 검증 전
- 기록일: 2026-09-11
- 출처: 기존 SSOT 설계 기본값의 결정 기록
- 관련 요구사항: PRD FR-03~07, NFR-01~03

## 배경

실적 한 건은 자재 소비, 완제품 입고, 지시 집계와 이력을 동시에 바꾼다.
같은 지시 또는 공통 자재를 사용하는 서로 다른 지시가 동시에 처리될 수 있다.
저장 성공 응답이 유실되면 사용자가 같은 작업을 다시 제출할 수 있다.

## 결정

READ COMMITTED 트랜잭션에서 지시를 잠그고 관련 재고 행을 품목 ID 순서로 잠근 뒤 수량을 검증한다.
실적·집계·재고 잔액·변동 이력을 같은 트랜잭션으로 저장한다.
품목 생성 시 재고 행을 만들어 존재하지 않는 행을 잠그려는 상황을 피한다.
모든 재고 변경 경로에서 같은 잠금 순서를 사용하며 DB 제약을 보조 방어로 적용한다.

입고·생산 지시 생성·실적 등록에 요청 식별자를 사용한다.
작업 종류와 키를 고유하게 저장하고, 정규화된 대상·본문 전체로 입력 해시를 만든다.
키 확보와 결과 저장은 업무 변경과 같은 트랜잭션에서 처리한다.
동일 요청은 기존 리소스를 반환하고 다른 입력의 키 재사용은 충돌로 거절한다.
응답·키 보존·실패 정책은 [SSOT 5절](../SSOT.md#5-트랜잭션과-정합성)을 따른다.

## 대안

| 대안 | 선택하지 않은 이유 |
| --- | --- |
| 읽은 수량을 확인하고 잠금 없이 갱신 | 확인 이후 다른 요청이 재고를 소비할 수 있다. |
| 낙관적 버전 검사 | 가능하지만 여러 자재를 묶는 충돌·재시도 흐름보다 현재 잠금 방식을 선택했다. |
| SERIALIZABLE 중심 처리 | 가능하지만 중단된 트랜잭션의 재시도 정책이 필요하며 현재 불변 조건은 명시적 잠금으로 처리한다. |
| 비동기 이벤트로 재고 반영 | 실적과 재고 사이의 지연·부분 실패 복구가 추가된다. |
| 제출 버튼만 비활성화 | 네트워크 재전송과 다중 탭·동시 요청을 막지 못한다. |

## 결과와 단점

정합성 경계를 하나의 DB 트랜잭션으로 설명하고 검증할 수 있다.
경쟁하는 쓰기는 대기하며 잠금 순서를 어기는 새 경로가 생기면 교착 위험이 있다.
요청 키 저장 공간과 입력 정규화 규칙도 유지해야 한다. 무조건적인 exactly-once 실행 보장을 주장하지 않으며, 보존된 키를 재사용한 요청에 한해 중복 반영을 막는다.
행 잠금과 교착 동작은 [PostgreSQL 공식 문서](https://www.postgresql.org/docs/current/explicit-locking.html)를 따른다.

## 검증과 재검토 조건

동일 지시 경쟁, 공통 자재 경쟁, 동일 키 경쟁, 입력이 다른 키 재사용, 중간 실패 롤백을 검증한다.
잠금 대기와 충돌이 실제 병목이 되면 트랜잭션 길이와 쿼리를 먼저 측정하고 대안을 재검토한다.
데이터를 여러 DB나 서비스로 분리할 경우 이 결정의 원자성 전제를 다시 설계한다.
