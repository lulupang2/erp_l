# ADR-0009: 현장 자재·품질·완제품 입고를 분리하는 생산 모델

- 상태: v2 목표 설계 채택 / 전체 구현 진행 중, 완료·인수 증거 대기
- 날짜: 2026-09-12
- 출처: 사용자가 실제 공장 흐름으로 계획 변경을 요청하고, 특정 공장 없는 소규모 조립·생산 중심 범위를 선택함
- 관련: [PRD v2](../PRD.md) F2-01~10, B2-01~14
- 관계: ADR-0006의 실적·완제품 동시 반영과 ADR-0007의 승인 없는 현재 BOM 사용을 v2에서 부분 대체. v1에는 기존 결정 유지.

## 배경

v1은 최소 데모를 위해 양품+불량을 계획 달성으로 보고 실적 때 BOM 자재를 일괄 차감했다.
사용자가 요청한 불출·반납·검사·불량 흐름을 표현하려면 현장 미소비 자재와 품질 상태를 구분해야 한다.
자동 차감 자체가 비현실적이라는 이유가 아니라, 이번에 선택한 명시적 현장 수불 요구를 표현하기 위해 바꾼다.

## 결정

- 목표를 합격 입고 수량으로 정의하고 착수 허용 수량과 분리한다.
- 불출/반납은 내부 이동, 생산 실제 소비는 출고로 기록한다. BOM은 제안값과 기준 개정이다.
- 산출 보고는 검사대기를 만들며, 검사와 합격품 입고를 별도 전표로 확정한다.
- 불량을 격리하고 폐기/재작업으로 처분한다. 재작업은 기존 산출물 상태를 이동하며 추가 자재만 소비한다.
- 승인 BOM/검사 기준을 고정하고 계정·역할·감사·역분개를 도입한다.
- 각 문서의 확정은 동일 DB 트랜잭션·일관된 잠금·요청 키로 보호한다. 공정 전체를 장시간 트랜잭션으로 묶지 않는다.
- v2를 별도 schema와 API 경로로 구현하고 v1 실적을 새 규칙으로 자동 재해석하지 않는다.
- 2026-09-12 사용자 결정에 따라 reverse proxy Basic Auth를 사용하지 않는다. v1 익명 조회·쓰기 위험은 남으며 v2 개별 사용자 세션·역할·감사는 별도 필수 요구다.
- 보류/입고·초과 합격·상태/역할·세션/요청 소유권·수량 기본값과 미정 정책은 [FACTORY-PLAN 7절](../FACTORY-PLAN.md#7-구현-인수-경계와-결정-게이트)과 [SSOT](../SSOT.md)에 고정한다. 승인 범위와 충돌하면 구현으로 임의 결정을 숨기지 않는다.

## 대안

| 대안 | 판단 |
| --- | --- |
| 기존 자동 차감에 상태 필드만 추가 | 불출·소비·반납과 품질별 잔량을 독립적으로 대조하기 어렵다. |
| 수주~회계 전체 ERP 도입 | 사용자 선택인 생산 중심 범위를 벗어난다. |
| MSA/MES 전체 플랫폼화 | 현장 흐름 개선에 필수이지 않으며 기존 단일 DB 정합성 이점을 잃는다. |
| 기존 데이터에 새 상태·목표를 추정해 부여 | 기록하지 않은 로트·검사·자재 이동을 사실처럼 만들 수 있어 채택하지 않는다. |

## 결과와 단점

목표 모델은 현장에 남은 자재와 품질별 미처리 수량, 문서 확정자를 추적하는 것이다. 아래 효과는 구현·인수 증거 전까지 목표이며 검증된 기능 주장이 아니다.
대신 입력 문서·승인·역분개 의존관계와 화면 수가 늘어난다. 전용 역할·로트 관리도 필요하다.
첫 범위를 개수 단위·단일 단계 조립·최종 검사로 제한한다. 세부 정책은 제품 기본값이며 실제 공장 검증 전이다.
기술 스택 선택은 유지하고 수량 의미와 업무 경계를 변경한다.

## 검증과 재검토

[전환 계획](../FACTORY-PLAN.md)의 단계별 인수와 실패/경쟁 시나리오를 따른다.
다공정·연속생산·외주·법정 품질 기준이 필요한 공장이 정해지면 PRD부터 재검토한다.
상태 채택과 구현 착수는 현재 서비스가 전체 v2를 구현·검증했음을 뜻하지 않는다. 준비 단계만이 아니라 F2-01~10 전체를 구현하며, 최종 통합 담당자가 제공한 실제 증거만 [PROGRESS](../PROGRESS.md)에 반영한다.
