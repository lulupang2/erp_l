# 소규모 조립공장 생산 흐름 전환 계획

작성일: 2026-09-12  
상태: 전체 v2 구현 진행 중 / 단계별 완료·인수 증거 대기

## 1. 범위와 기준

사용자는 특정 업체 없이 소규모 조립공장을 기준으로 생산 중심 흐름을 선택했다.
계획은 [PRD v2](PRD.md)의 F2/B2 정책과 [SSOT v2](SSOT.md)를 따른다.
수주·구매·출하·회계 전체 ERP로 확대하지 않는다. 기존 기술 스택과 모듈형 모놀리스를 유지한다.
새 정책은 구현 중인 목표 계약이다. 범위는 단계 0 준비에 한정되지 않으며 F2-01~10 전체다. 작성된 코드·DDL의 존재나 작업자 시작을 실행 중인 서비스의 v2 구현·전환 완료로 간주하지 않는다.

## 2. 현재와 목표의 차이

| 영역 | 구현된 v1 | 구현 중인 v2 목표 |
| --- | --- | --- |
| 목표 | 양품+불량 처리 수량 | 합격 후 입고 목표, 추가 착수는 별도 승인 |
| 자재 | 실적 시 BOM대로 창고 차감 | 불출·실제 소비·반납·손실 구분 |
| 재고 | 품목별 한 잔액 | 품목·로트·위치·지시 소유 구분 |
| 생산 | 양품·불량 직접 입력 | 실제 소비 연결 산출 보고 후 검사 |
| 불량 | 회수 없는 전량 소비 | 격리·폐기·재작업·재검사 |
| 완제품 | 실적 즉시 양품 재고 증가 | 검사 합격 미입고와 입고 완료 분리 |
| 완료 | 처리 수량 도달 시 자동 완료 | 목표 달성 및 현장·품질 정리 후 명시적 마감 |
| BOM | 현재 BOM을 지시에 복사 | 승인 개정 고정, 실제 소비 차이 기록 |
| 추적 | 원인 문서 | 원인 문서·투입/산출 로트·사용자·정정 이력 |
| 정정 | 기능 없음 | 후속 의존관계 확인 후 역분개·재입력 |
| 접근 | 앱 로그인 없음 | 서버 세션·역할별 권한 |

## 3. 구현 단계와 종료 조건

### 단계 0 — 기존 배포 문제와 전환 준비

- 기존 리뷰 지적을 후속 결정·수정·검증별로 추적한다. Basic Auth 복구 요구는 사용자 no-proxy-auth 결정으로 대체하며 v1 익명 조회·쓰기 위험을 기록한다. 다른 배포 수정과 문서 정합화도 증거 없이 완료 처리하지 않는다.
- v1 계약·스키마·테스트 기준을 유지하고 v2 전용 API 경로·schema·DB 역할을 준비한다.
- v2 OpenAPI와 실제 DDL을 작성해 요구사항/테이블/전표 연결을 검토한다. 기존 ERD는 v1로 남긴다.
- 완료 조건: v1 회귀 통과, v2 테스트가 명시적으로 격리된 loopback erp_test만 사용, 데이터 자동 재해석 없음.

### 단계 1 — 역할·기준정보·자재 수불

- 관리자 발급 계정, 다중 역할, 서버 세션, 감사 기록과 상태 변경 권한을 구현한다.
- 품목·논리 위치·로트·BOM 개정·검사 기준, 작업 지시 초안/발행을 구성한다.
- 부품 입고, 지시 현장 불출·추가 불출·반납·자재 손실의 초안/확정/정정을 구현한다.
- 완료 조건: F2-01~04, 불출 시 총 자재 보존, 경쟁 불출에서 음수 없음, 과다 반납·무권한 확정 거절.

### 단계 2 — 생산 보고·최종 검사·완제품 입고

- 작업 세션의 시작/종료와 부분 생산 보고를 만든다. 실제 소비는 투입 로트별로 기록한다.
- 검사대기 산출 로트, 부분 검사, 합격 미입고, 완제품 부분 입고를 연결한다.
- 계획 입고 목표와 허용 착수량을 분리하고 목표 변경/추가 착수의 사유와 담당자를 기록한다.
- 완료 조건: 검사 이전 입고 불가, 중복 검사/입고 방지, 생산 보고 후 검사/입고에서 자재 재차감 없음.

### 단계 3 — 불량·재작업·마감·정정

- 부적합 처분, 재작업 생성, 추가 소비, 재검사와 반복 재작업 이력을 연결한다.
- 보류/재개, 정상 마감, 조기종결, 문서 의존관계에 따른 역분개를 구현한다.
- 모든 전표와 합계에 대해 원장·잔액·산출 상태 대조를 제공한다.
- 완료 조건: 재작업이 신규 산출을 늘리지 않음, 미해결 품질/자재가 있으면 마감 거절, 정정 시 전체 영향 일치.

### 단계 4 — 현장 시나리오 검증과 도입 판단

- 역할별 브라우저 시연, 동시 요청·응답 유실·중간 실패, v1/v2 격리와 전환 리허설을 수행한다.
- PRD 대표 시연의 자재 11/882 소비, 완제품 10 입고, 폐기품 1, 반납 1/78을 대조한다.
- 제한된 데모 환경에서 먼저 검증한다. 실제 공장 운영을 시작하려면 담당자에게 공정·품질·권한·정정 규칙을 검증받는다.
- 완료 조건: F2-01~10과 B2-01~14 인수 통과, 실행/복구 안내와 검증 증거 기록. 과거 v1 테스트만으로 완료하지 않는다.

## 4. 필수 실패·경쟁 시나리오

| 시나리오 | 기대 결과 |
| --- | --- |
| 두 지시가 같은 로트 불출 | 가용 창고 수량 이내만 성공 |
| 불출 재전송 | 동일 키는 한 전표만 생성 |
| 소비한 자재 반납 | 현장 미소비분을 초과하면 거절 |
| BOM과 다른 실제 소비 | 차이 사유 기록, 실제 로트별 수량만 차감 |
| 신규 산출 허용량 초과 | 추가 착수 승인 없으면 거절 |
| 검사대기 5에 검사 3·3 동시 제출 | 합계 5 초과 판정 불가 |
| 부적합 수량 동시 폐기·재작업 | 같은 물량에 중복 처분 불가 |
| 재작업 2개에 자재 0 또는 2개 사용 | 실제 추가 소비만 반영, 신규 생산량 변화 없음 |
| 합격 7에 입고 5·5 동시 제출 | 합계 7 초과 입고 불가 |
| 목표 10에 합격 11 | 검사 결과 보존, 초과 입고는 목표 변경 전 거절 |
| 계획 달성했으나 자재/품질 잔량 존재 | 자동 종료하지 않고 마감 거절 |
| 후속 입고가 있는 검사 취소 | 입고를 먼저 역분개하기 전 거절 |
| 전표 확정 중 실패 | 전표·원장·집계·감사 기록 전부 롤백 |
| 세션 만료/역할 철회 후 키 재전송 | 권한 재검사로 결과/업무 접근 차단 |
| v1 완료 10(양품7·불량3) | v2 합격10으로 변환하지 않음 |

## 5. 데이터 이전과 배포

1. 기존 v1 백업과 잔액 대조 결과를 확보한다. 기존 migration을 고쳐 과거 데이터의 의미를 바꾸지 않는다.
2. 별도 schema/역할에 v2를 추가하고 로컬 격리와 권한을 검증한다. 이 문서 정합화 작업은 실제 자원 생성이나 DB 변경을 수행하지 않는다. Neon/production 변경은 별도 승인·절차·증거 없이 실행하지 않는다.
3. 같은 실물을 v1과 v2가 동시에 기록하지 않도록 대상과 전환 기준 시각을 정하고 v1 쓰기를 동결한다.
4. 기존 미완료 지시는 v1 기준으로 정리한다. 현장 재공을 파악하지 못하면 해당 대상의 이전을 보류한다.
5. 실사한 기초 자재·완제품 수량과 위치를 승인 전표로 반영한다. 과거 로트가 없으면 출처 미확인임을 표시하고 실제 로트 추적 완료라고 주장하지 않는다. 사용 가능 여부는 전환 담당자가 확인한다.
6. 원천 잔액과 새 기초 전표를 대조한 후 v2를 사용한다. 과거 실적은 v1 조회로 보존한다.
7. v2 실물 거래가 시작된 후에는 단순히 옛 이미지만 실행해 v1 쓰기로 복귀하지 않는다. 신규 거래를 대조·정리하고 별도 복구 절차를 거친다.

포트폴리오 시연은 새로운 합성 데이터로 시작할 수 있으나 기존 Neon 데이터를 삭제하지 않는다.
서비스가 v2를 채택하더라도 이전 실행/검증 기록은 날짜·버전과 함께 보존한다.

## 6. 아직 현장 검증하지 않은 항목

작업자의 실제 입력 단위, BOM 대비 소비 차이 허용, 로트 혼합, 품질 항목,
재작업 승인 권한과 목표 초과 처리, 교대별 마감과 실사 방법은 특정 업체 확인이 없다.
현재 PRD의 기본값으로 데모를 구현할 수 있지만 실제 현장 적용 전 검증해야 한다.
이번 범위에서 미결정된 네트워크·센서·원가·설비 기능을 추가하지 않는다.

## 7. 구현 인수 경계와 결정 게이트

아래는 PRD 역할·보류·정정 정책과 기존 정수 제한을 명령으로 옮기기 위한 **보수적 구현 기본값 및 인수 조건**이다. 새로운 승인 범위나 구현 완료 선언이 아니다. 기존 승인 정책과 충돌하거나 별도 처분/권한이 필요하면 해당 동작을 열지 말고 통합 담당자에게 결정을 요청한다. 모든 미열거 상태/역할 조합은 기본 거절한다.

### 상태·역할 전이

| 명령 | 수행 역할 및 허용 상태 | 필수 거절/보존 조건 |
| --- | --- | --- |
| 지시 초안 생성·수정·발행 | 생산관리; 초안 → 발행 | 승인 BOM/검사 기준·담당자·목표·허용 착수량 고정. 발행 후 직접 수정 대신 승인 변경 |
| 작업 시작·부분 산출·종료 | 배정된 작업자; 발행/작업 중에서 시작, 최초 시작은 작업 중으로 전이 | 산출은 본인 진행 작업 세션에 귀속. 종료는 미보고 산출을 자동 생성하지 않음 |
| 보류·재개 | 생산관리; 발행/작업 중 → 보류 → 보류 직전 상태 | 이전 상태 보존. 초안·종료 상태의 보류/재개 거절 |
| 추가 착수·목표 변경 | 생산관리; 발행/작업 중/보류, 사유·변경 전후 기록 | 자동 목표 증가 없음. 목표를 순입고 미만, 허용 착수를 이미 산출/진행 예약된 수량 미만으로 감소 금지 |
| 부품 입고·불출·반납·자재 손실 | 자재담당; 지시별 불출은 발행/작업 중 | 미소비 현장 자재만 반납/손실 가능. 부품 창고 입고는 특정 지시 보류와 독립 |
| 검사·부적합 처분·재검사 | 품질담당; 발행/작업 중/보류의 해당 원천 잔량 | 재작업 처분은 품질담당, 실제 재작업은 배정 작업자. 이미 처분된 수량 재사용 금지 |
| 합격품 부분 입고 | 자재담당; 발행/작업 중 | 미입고 합격분·목표 잔량 이하; 보류는 재개 전 거절 |
| 정상 마감·조기종결 | 생산관리; 작업 중, 또는 보류 해제 후 | PRD B2-11/12 정리 조건 및 정상 목표 달성/조기 부족 사유 필요 |
| 지시 취소 | 생산관리; 초안 또는 활동 없음/전부 역분개한 발행 | 작업 중 지시를 직접 취소해 활동 삭제 금지. 기록은 보존 |
| 전표 역분개·정정 | 관리자 승인과 해당 전표 수행 역할 | 후속 의존관계부터 역순 정리, 음수 거절. 관리자 역할만으로 모든 생산 명령을 허용하지 않음 |
| 계정·역할·기준정보 승인 | 관리자 | 사용자 ID/역할을 본문으로 신뢰하지 않음; 비활성 계정·철회 권한 즉시 거절 |

초안 전표의 작성/수정/확정은 해당 업무 역할과 작성자 소유를 함께 확인한다. 관리자의 정정 승인은 타인의 초안을 자동 소유하거나 작업 세션을 대행할 권한이 아니다. 배정 변경은 생산관리의 기록된 명령으로 처리하되 타인의 진행 작업을 강제로 종료·인계하는 정책이 필요하면 별도 결정한다.
마감·조기종결·취소는 종료 상태로 두고 임의 재개/새 거래를 거절한다. 종료 지시의 역분개에 재개가 필요하면 감사 가능한 재개 정책 결정이 선행되어야 하며, 정정 F2-09 전체를 생략하는 근거로 쓰지 않는다.

### 보류·초과 합격의 경계

- 보류는 신규 불출·작업 시작·신규 산출/소비·실제 재작업과 합격품 입고를 차단한다. 보류 전 작성한 초안도 확정 시 현재 상태를 다시 검사한다.
- 반납·검사·소비 없는 부적합 폐기/재작업 처분·역분개와 진행 작업 종료는 정리를 위해 허용한다. 재작업 처분을 실제 재작업 시작으로 간주하지 않는다.
- 목표 10, 순입고 10, 합격대기 1이면 합격 기록을 유지하고 추가 입고·마감을 거절한다. 목표 11 승인 후 1 입고와 잔량 정리가 보수적 경로다. 합격품 폐기/출하/불량 위장 처리는 승인 범위에 없다.

### 세션·요청 소유권과 수량

- 로그인 세션과 작업 세션을 구분한다. 계정/역할은 서버가 결정하며, 작업 세션은 지시·배정 작업자·진행 상태를 가진다. 로그아웃/만료는 진행 작업 수량을 없애지 않는다.
- [SSOT 5절](SSOT.md#5-권한과-동시성)의 계정+작업+키 소유권, 재로그인 재응답, 권한 철회, 계정 전환 시 브라우저 요청 격리를 검증한다. UI 버튼 숨김만으로 권한 통과를 선언하지 않는다.
- [SSOT 수량 한도](SSOT.md#31-수량-한도와-계산-기본값)를 DTO·OpenAPI·서비스·DDL에서 일치시킨다. 0/최댓값/최댓값+1, 여러 행 합산, BOM 곱셈, 동시 승인/입고와 역분개를 포함한다.
- 진행 작업에 수량을 예약하는 모델이면 여러 세션의 예약+산출이 허용 착수량을 넘지 않도록 해야 한다. 예약을 기록하지 않는 모델이라면 시작만으로 수량 보장을 주장하지 말고 산출 확정 한도를 검증한다. 실제 모델과 API 전이는 구현 전에 통합 담당자가 명시한다.

### 최종 통합에서 필요한 증거

명령별 성공·잘못된 역할/상태 거절, 보류 중 초안 확정 경쟁, 계정 간 같은 키/같은 전표 경쟁, 세션 만료·권한 철회 후 재응답, 초과 합격 대기 및 목표 승인 후 입고를 확인한다.
종료 후 정정/재개, 작업 배정 인계, 로그인 세션 만료 기간·계정 초기 발급 방식의 구체 계약은 구현 담당자가 확정해 기록해야 한다. 충돌하는 정책은 사용자 결정을 받아 반영하며 누락 기능을 완료로 표시하지 않는다.
F2-01~10 및 B2-01~14 전체 연결, v1/v2 데이터·권한 격리, PRD 대표 시연의 수량 대조, 실제 UI와 복구 흐름의 최종 결과가 필요하다. 병렬 문서 작업 중에는 테스트·빌드·포매터·린터나 DB/클라우드 변경을 실행하지 않는다.
