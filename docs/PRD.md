# 조립 제조 ERP — PRD v2

문서 버전: 2.0 초안  
작성일: 2026-09-12  
상태: 소규모 조립공장 생산 흐름 v2 전체 구현 진행 중 / 완료·인수 검증 대기

## 1. 목적과 기준

생산 담당자, 자재 담당자, 작업자와 검사자가 작업 지시부터 완제품 입고까지 실제 처리 내역을 공유하는 ERP를 만든다.
특정 공장을 위한 운영 적합성 검증은 아직 하지 않았다. 소규모 조립공장의 대표 흐름을 선택한 포트폴리오 계획이며 모든 공장의 표준이라고 주장하지 않는다.

사용자가 확정한 범위는 **작업 지시 → 자재 불출·반납 → 생산 → 검사·불량 → 완제품 입고**다.
기존 v1의 처리 수량 목표·실적 시 일괄 자재 차감 규칙을 v2에서 대체한다.
[v1 PRD](PRD-V1.md)는 기존 코드와 데이터의 기준으로 보존한다. 기존 테스트 통과를 v2 완료로 간주하지 않는다.

- 제품 요구와 정책: 이 문서
- 목표 데이터·API·정합성: [SSOT](SSOT.md)
- 전환 순서·호환성·인수 시나리오: [FACTORY-PLAN](FACTORY-PLAN.md)
- 결정 배경: [ADR 목록](adr/README.md)
- 실제 구현 상태: [PROGRESS](PROGRESS.md)

## 2. 목표와 범위

### 목표

- 계획 수량뿐 아니라 생산 중인 수량, 검사대기, 불량 보류, 입고 완료와 잔여 필요량을 구분한다.
- 창고에서 현장으로 보낸 자재와 실제 소비한 자재, 남아 반납할 자재를 구분한다.
- 누가 언제 어느 지시·로트에 대해 처리했는지 추적하고 잘못된 입력을 이력을 보존하며 정정한다.

### 첫 v2 릴리스의 기본 가정

하나의 회사·공장, 개수 단위의 조립품, 단일 단계 BOM과 조립→최종 검사 흐름을 적용한다.
작업 지시는 수동 생성하며 계획 수량은 **검사 합격 후 완제품 입고 목표**다.
수주·MRP·구매 없이 부품 입고 문서로 시작한다. 정수 수량을 유지하고 kg·m·단위 환산은 제외한다.

원자재 창고, 작업 지시별 현장 자재, 검사대기, 합격대기, 부적합 격리, 재작업 중, 완제품 창고를 논리적으로 구분한다.
자재와 생산 산출물은 로트 단위로 기록한다. 개별 제품 일련번호와 다중 공장 관리는 제외한다.
이러한 세부 선택은 이번 범위에 맞춰 정한 설계 기본값이며 특정 업체가 확인한 요구는 아니다.

### 포함 기능

| ID | 요구사항 | 인수 조건 |
| --- | --- | --- |
| F2-01 | 사용자와 책임 구분 | 계획·자재·작업·검사·관리 역할에 맞는 서버 권한 검증과 작성자 기록 |
| F2-02 | 기준정보 | 품목, 위치, 불량 사유, BOM 개정의 초안·승인·사용 중지 관리 |
| F2-03 | 작업 지시 | 완제품·합격 입고 목표·착수 허용 수량·예정일·담당자·승인 BOM을 지정해 발행 |
| F2-04 | 부품 입고·불출·반납 | 부품 입고 로트, 창고→지시 현장 이동, 추가 불출, 미소비분 반납 기록 |
| F2-05 | 생산 보고 | 실제 소비한 부품 로트/수량과 새로 조립한 산출 수량을 연결해 확정 |
| F2-06 | 검사 | 생산 로트에 대한 부분 검사와 항목별 판정, 합격/부적합 수량 기록 |
| F2-07 | 부적합 처리 | 불량 사유·폐기·재작업 처분과 재검사, 추가 자재 소비 기록 |
| F2-08 | 완제품 입고 | 검사 합격분만 부분 입고하며 같은 합격 수량의 중복 입고 차단 |
| F2-09 | 종료·정정 | 목표 달성과 정리 상태 확인 후 명시적 마감, 사유·권한을 갖춘 조기종결과 역분개 정정 |
| F2-10 | 조회·추적 | 지시별 자재 수불·생산/검사/입고 집계, 로트별 원인 문서와 사용자 추적 |

### 제외 및 후속

수주·구매·출하·회계·원가, 자동 자재소요계획, 설비 연동·OEE, 유한능력 일정계획,
외주·다공정 공정별 실적, 다단계 BOM·반제품 재고, 대체품 자동 투입, 자재 예약,
샘플링 검사·AQL·법정 품질 인증, 해체·소비 자재 회수는 제외한다.
수입 검사와 출하 검사는 후속이다. 이번 부품 입고는 사용 가능한 것으로 확인한 자재만 받는다.

## 3. 역할

| 역할 | 책임 |
| --- | --- |
| 생산관리 | 지시 발행·보류·추가 착수 승인·마감, 목표 변경과 조기종결 사유 기록 |
| 자재담당 | 부품 입고, 지시별 불출·반납, 합격품 입고 |
| 작업자 | 배정된 지시의 조립 시작·생산 보고, 재작업 수행 |
| 품질담당 | 검사, 부적합 판정과 폐기/재작업 처분, 재검사 |
| 관리자 | 계정·역할·기준정보 승인, 정정 승인과 감사 조회 |

계정 하나가 여러 역할을 가질 수 있다. 첫 버전에서는 모든 공정에 2인 승인을 강제하지 않지만 사용자와 수행 역할을 기록한다.
사용자 결정에 따라 reverse proxy Basic Auth는 사용하지 않는다. v1은 앱 로그인·권한이 없어 공개 접근자에게 익명 조회·쓰기를 허용하는 위험이 있다. TLS나 네트워크 바인딩을 사용자 인증으로 간주하지 않는다. v2의 개별 사용자 세션·서버 역할 검증·감사는 이 결정과 별개의 필수 요구이며 구현 완료 증거는 PROGRESS에서 관리한다.

## 4. 핵심 업무 규칙

| ID | 정책 |
| --- | --- |
| B2-01 | 목표는 합격 후 입고할 수량이다. 불량은 목표 달성에 포함하지 않는다. |
| B2-02 | 최초 착수 허용 수량은 목표와 같다. 불량 보충을 위한 추가 조립은 생산관리의 추가 착수 승인을 받으며 목표는 자동 증가하지 않는다. |
| B2-03 | 총 신규 산출 수량은 승인된 착수 허용 수량을 넘지 않는다. 재작업은 기존 산출물의 상태 변경으로 신규 산출에 다시 더하지 않는다. |
| B2-04 | 불출은 창고→지시별 현장 이동이다. 회사 전체 자재량은 변하지 않으며 다른 지시는 이 자재를 사용할 수 없다. |
| B2-05 | 생산 보고에서 실제 소비량을 확정한다. BOM 소요량은 제안값이며 차이는 사유를 기록한다. 실제 소비는 해당 지시·로트의 현장 가용 수량 이하여야 한다. |
| B2-06 | 자재 손실은 생산 산출과 별도 폐기 문서로 기록한다. 미소비 자재만 반납하며 이미 소비한 자재를 반납으로 되살리지 않는다. |
| B2-07 | 조립 산출물은 우선 검사대기다. 작업자가 양품으로 입력했다는 이유로 완제품 재고에 넣지 않는다. |
| B2-08 | 검사 수량은 대상 로트의 미검사 수량 이하다. 판정 후 합격 또는 부적합 격리로 이동하며 검사 시 자재를 다시 차감하지 않는다. |
| B2-09 | 부적합은 품질담당이 폐기 또는 재작업으로 처분한다. 재작업은 원산출 로트와 연결하고 실제 추가 자재만 소비한 뒤 다시 검사한다. |
| B2-10 | 완제품 입고는 미입고 합격 수량 이하다. 목표 초과 입고는 기본 거절하며 생산관리의 목표 변경 승인이 있어야 허용한다. |
| B2-11 | 목표 달성만으로 자동 마감하지 않는다. 진행 작업, 검사대기, 합격 미입고, 부적합 미처분, 재작업, 미소비 현장 자재가 남으면 마감할 수 없다. |
| B2-12 | 부족 상태의 조기종결은 생산관리 사유 기록과 위 정리를 요구한다. 남은 수량은 자동 삭제/성공 처리하지 않고 부족분으로 보존한다. |
| B2-13 | 확정 문서는 직접 수정·삭제하지 않는다. 원문서를 참조하는 역분개로 취소하고 새 문서로 재입력한다. 후속 소비·검사·입고가 있으면 역순으로 정리 전까지 취소를 거절한다. |
| B2-14 | 지시 발행 시 승인된 BOM 개정을 고정한다. 기존 지시를 최신 BOM으로 자동 바꾸지 않는다. 실제 소비 차이는 실적에 기록한다. |

부품 손실과 조립품 불량은 별도 수량이다. 조립품 1개가 불량이어도 모든 BOM 부품을 추가 폐기한 것으로 기록하지 않는다.
공정 시간이 길어 조립 중인 작업은 진행 상태로 남기며 완료된 일부 수량만 산출 보고한다.
전수 최종 검사를 기본으로 하되 검사 항목과 합격 기준은 제품별 승인된 검사 기준을 사용한다.

## 5. 문서와 상태 흐름

- 작업 지시: 초안 → 발행 → 작업 중 → 마감. 발행/작업 중은 보류·재개 가능하다.
- 취소: 초안 또는 활동이 없거나 관련 기록을 모두 역분개한 발행 지시만 가능하다.
- 조기종결: 실제 처리 기록이 있는 지시를 부족 사유와 함께 닫는 별도 종료 상태다.
- 작업 세션: 시작 → 진행 → 종료. 부분 산출 보고가 가능하고 진행 작업이 남으면 지시 마감을 막는다.
- 수불·생산·검사·처분 문서: 초안 → 확정 → 역분개 완료. 초안은 재고에 영향이 없다.
- 생산 로트: 미검사 / 합격 미입고 / 입고 완료 / 부적합 보류 / 재작업 중 / 폐기 수량을 나누어 관리한다.
- 지시 보류는 신규 불출·조립·소비를 막되, 반납·검사·처분과 정정은 허용한다.

잔여 목표는 max(목표 - 순입고, 0)이다. 최초 검사 합격률과 재작업 후 최종 합격률은 서로 다른 지표로 표시한다.
검사 반복 횟수를 누적 생산량이나 불량 제품 수로 오해하지 않도록 현재 상태 수량과 검사 이력을 분리한다.

### 구현 전 고정할 인수 경계

전체 F2-01~10 범위는 유지한다. 명시되지 않은 상태/역할 조합은 허용하지 않는 기본값을 적용하고 [FACTORY-PLAN 7절](FACTORY-PLAN.md#7-구현-인수-경계와-결정-게이트)에 명령별 전이·역할·거절 조건을 정리한다.
보류 중 합격품 입고는 재개 전까지 거절하는 보수적 기본값으로 두며, 반납·검사·비소비 처분·정정과 작업 종료는 허용한다. 재작업 처분은 가능하지만 실제 재작업 시작·추가 소비는 재개 후에만 가능하다.
초과 합격분은 합격 미입고로 보존하고 승인된 목표 증가 후 입고한다. 합격품 임의 폐기·불량 재분류·목표 자동 증가를 우회 경로로 추가하지 않는다. 다른 처분이 필요하면 구현 전에 정책 결정을 받아야 한다.
로그인 세션과 작업 세션은 다른 개념이며, 요청 키 소유권·역할 철회 후 재응답·수량 상한은 [SSOT 5절](SSOT.md#5-권한과-동시성)과 [수량 규칙](SSOT.md#31-수량-한도와-계산-기본값)을 따른다.

## 6. 대표 시연

완제품 1개에 케이스 1개·스위치 80개가 필요한 제품으로 합격 입고 목표 10개를 발행한다.

1. 케이스 12개·스위치 960개를 입고하고 지시에 불출한다. 소비는 아직 0이다.
2. 신규 10개를 조립해 케이스 10개·스위치 800개를 소비한다. 검사대기 10개, 현장 잔여 자재 2개/160개다.
3. 검사에서 7개 합격·3개 부적합을 기록하고 합격 7개를 입고한다. 잔여 목표는 3개다.
4. 부적합 1개는 폐기, 2개는 재작업한다. 새 스위치 2개를 추가 소비하고 2개 모두 재검사 합격 후 입고한다.
5. 생산관리가 1개의 추가 착수를 승인한다. 새 제품 1개를 조립하고 케이스 1개·스위치 80개 소비, 검사 합격 후 입고한다.
6. 현장 잔여 케이스 1개·스위치 78개를 반납하고 모든 작업을 종료한 뒤 지시를 마감한다.

최종 순입고 10개, 신규 산출 11개, 폐기 조립품 1개, 재작업 후 회복 2개다.
자재 소비 합계는 케이스 11개·스위치 882개, 창고 잔여는 1개·78개이며 현장 잔여는 0이다.
재작업의 교체된 스위치는 이미 원생산에서 소비한 자재다. 추가 창고 차감이나 회수 입고를 하지 않는다.

## 7. 인수 조건

- 불출만으로 총 자재 재고가 줄지 않으며 실제 소비와 반납이 중복 반영되지 않는다.
- 검사 전·부적합·폐기 수량은 완제품 가용 재고로 입고할 수 없다.
- 재작업 합격은 기존 산출물 수량만 이동하며 생산량과 전체 BOM 소비를 중복 증가시키지 않는다.
- 같은 키 재전송·경쟁 불출·경쟁 검사·경쟁 입고에도 수량 한도를 지킨다.
- 권한 없는 확정·추가 착수·목표 변경·정정을 서버에서 거절한다.
- 문서 실패는 재고·집계·상태·감사 기록이 함께 롤백된다.
- 로트/위치별 잔액, 소비/반납, 산출 상태 합계가 이력과 일치한다.
- 6절을 재현하며 권한·불량·반납·조기종결·역분개 오류 흐름도 검증한다.

## 8. 구현과 전환

Go Fiber, SvelteKit + TypeScript, sqlc + pgx, Goose, Neon, 모노레포·모듈형 모놀리스를 유지한다.
계획 변경 이후 후속 요청으로 전체 v2 구현을 진행한다. 문서·코드 작성이나 작업자 시작만으로 코드·DB 전환과 인수 완료를 주장하지 않는다. 상세 단계와 기존 데이터 보호는 FACTORY-PLAN을 따른다.
v1의 계획 10·양품 7·불량 3을 v2의 목표 달성 10으로 재해석하지 않는다.

## 9. 참고와 적용 한계

자재 이동·소비·반납을 나누는 흐름은 [ERPNext Stock Entry](https://docs.frappe.io/erpnext/stock-entry)와
[Work Order](https://docs.frappe.io/erpnext/work-order), 검사 분리는 [Quality Inspection](https://docs.frappe.io/erpnext/quality-inspection)을 참고했다.
이 서비스의 역할, 목표 수량, 추가 착수, 재작업 집계와 마감 규칙은 해당 문서를 복제한 표준이 아니라 이 프로젝트의 설계 결정이다.
실제 공장 도입 전에는 현장 담당자와 공정, 불량 처분, 품질 기준, 권한·정정 절차를 검증해야 한다.
